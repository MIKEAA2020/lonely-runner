## 2. What exactly was tested, and why the computation is exact

### 2.1 Formulation

For v_1 < ... < v_n distinct positive integers, delta = 1/(n+1), the polytope
tested is the document's P(v), written with integer coefficients:

  P(v) = { k in R^n :  0 <= k_i <= v_i - 1,
           (n+1)(v_j k_i - v_i k_j) <= n v_i - v_j   for all i != j }.

Equivalence used (derived in the document, re-derived and re-verified here):
a lonely time exists iff there is a t with ||t v_i|| >= delta for all i, iff
the intervals [(k_i + delta)/v_i, (k_i + 1 - delta)/v_i] have non-empty
intersection over some integer choice of k_i, iff P(v) contains an integer
point. All inequalities are non-strict on both sides, so there are no
strictness traps at equality (tight cases are included and certified).

**Proposition (LP relaxation is always non-empty).** For every v,
k_i = (v_i - v_1)/((n+1) v_1) lies in P(v).

*Proof.* Write w_i = (k_i + delta)/v_i (the left endpoint of runner i's time
window). The pair constraints say w_i <= w_j + (1 - 2 delta)/v_j for all i, j.
The point w_i = delta / v_1 lies in every window-range [delta/v_i,
1 - (1-delta)/v_i]: the lower bound holds because v_1 <= v_i, and the upper
bound delta/v_1 <= (v_i - 1 + delta)/v_i rearranges to
delta (v_i - v_1) <= v_1 (v_i - 1), which holds since delta < 1 <= v_1 and
v_i - v_1 <= v_i - 1. Substituting w_i = delta/v_1 gives constraints
0 <= (1 - 2 delta)/v_j, true since delta = 1/(n+1) < 1/2. The corresponding
k_i = (v_i - v_1)/((n+1) v_1) satisfies 0 <= k_i <= v_i - 1 by the same
inequality. For n = 1 there are no pair constraints. ∎

This was also verified numerically: 2,550 exact rational spot-checks (500 per
n = 1..5), all valid. Hence "P(v) real-feasible" carries no information in the
tested range (and provably none in general); the document's criterion
"real-feasible but integer-infeasible" reduces exactly to "integer-infeasible",
i.e. to failure of the Lonely Runner Conjecture itself.

### 2.2 Exact algorithm

gap(v) = max_{t in [0,1]} min_i ||t v_i|| was computed exactly in integer
arithmetic. The function g(t) = min_i ||t v_i|| is continuous and piecewise
linear, so its maximum is attained at a breakpoint of g. Breakpoints of g are
contained in: breakpoints of the individual sawtooths ||t v_i||, i.e. the peaks
t = odd/(2 v_i) (valleys t = m/v_i force g = 0 and cannot host a positive
maximum), and crossings ||t v_i|| = ||t v_j||, i.e. t (v_i + v_j) in Z or
t (v_i - v_j) in Z. Each candidate t = a/b is evaluated as
min_i min((a v_i) mod b, b - (a v_i) mod b) / b — pure integer arithmetic,
no floating point anywhere. gap(v) >= 1/(n+1) is decided by the integer
comparison (n+1) * num >= den.

Witness construction: for an argmax t* = a/b, set k_i = floor(t* v_i); then
t* v_i in [k_i + delta, k_i + 1 - delta] for all i, so k is an integer point
of P(v). Every witness was checked against all n(n-1) pair constraints and
bounds at runtime, and re-checked independently afterwards (layer L1 below).

## 3. Validation layers

Six independent layers, all passing:

- **L1 — full re-verification:** every one of the 2,369,935 dumped witnesses
  re-checked against all constraints with numpy (vectorized exact integer
  arithmetic). Violations: 0. Feasibility flags consistent with gaps: yes.
- **L2 — independent reference implementation:** an exact implementation
  written separately in pure Python (same breakpoint theorem, different code
  path, `fractions`-free integer arithmetic) was compared record-by-record on
  samples: all 1,225 vectors for n=2, 2,000 random for n=3, 600 each for
  n=4, n=5 (plus 50 for n=1). Gap mismatches: 0. Feasibility mismatches: 0.
- **L3 — literal ILP enumeration:** the C program's `brute` mode enumerates the
  *entire* k-box {0,...,v_i-1}^n and counts every integer point satisfying all
  constraints — the document's proposed check executed in the most literal way.
  Run over **all** v with v_n <= 12: n=2: 66 vectors (321 integer points),
  n=3: 220 (1,164), n=4: 495 (3,129), n=5: 792 (5,076). Verdict agreement with
  the run-mode sweep: **100%** (1,573/1,573).
- **L4 — third-party MILP solver:** HiGHS (scipy.optimize.milp) solved 444
  sampled instances (100 random per n = 2..5, 30 for n=1, plus all document
  rows and tight/second-tightest families). Returned points re-verified
  exactly. Disagreements: 0.
- **L5 — document claims:** see section 5.
- **L6 — structural invariants:** gap(d v) = gap(v) verified on 78,082 scaled
  pairs (violations: 0); bounded-speed criterion v_n <= n v_1 ⟺ k = 0 feasible
  verified on all vectors; LP explicit point verified on 2,550 samples.

### 4.4 The document's next-step #2: gap vs. overlap bound

The document's overlap-improved union bound certifies loneliness at level
delta < 1/(2n - 2(n-1)/v_n). Checked on every vector: **gap(v) >= that
threshold in all 2,369,935 cases** (0 violations) — the document's claim (b)
verifies universally. But the overlap bound reaches 1/(n+1) only when v_n <= 2:
among all n >= 2 vectors in range it certifies the conjecture for exactly one
vector, v = (1,2). This quantifies precisely how far union-bound-type arguments
remain from the conjecture, matching the document's diagnosis.

Bounded-speed reduction (document's one-line proof): among n=4 vectors, 98,346
(42.7%) have v_n <= 4 v_1 and are certified by k = 0; for n=5, 882,595 (41.7%).
The remaining 57-58% require non-zero shifts — and all of them have them.

## 6. Errata against the preceding document

- **E1 (substantive).** Table "Small-case verification", row v = (1,3,4),
  claimed integer point k = (0,0,1). It violates constraint (i,j) = (3,2):
  (n+1)(v_2 k_3 - v_3 k_2) = 4(3*1 - 4*0) = 12 > n v_3 - v_2 = 3*4 - 3 = 9,
  i.e. 3 > 9/4. The claimed lonely time t = 3/7 *is* valid
  (||3/7||, ||9/7||, ||12/7|| = (3/7, 2/7, 5/7) >= 1/4); the correct witness
  at that time is k = (0,1,1), and gap(1,3,4) = 2/7. The brute-force
  enumeration finds exactly 2 integer points for this v, neither of them
  (0,0,1).
- **E2 (annotation).** Table "hand verification", row v = (1,3), k = (0,1):
  claimed "(1,2) equality". No constraint is tight for this witness (the
  feasible t-window is [4/9, 5/9], non-degenerate); moreover equality in the
  document's condition v_1(1+k_2) - v_2 k_1 = (v_1+v_2)/3 = 4/3 is impossible
  for integer k since the left side is an integer.
- **E3 (annotation).** Row v = (1,3,5), k = (0,0,1), and the section-4 text
  "equality at (i,j) = (1,3)": the actual equality pairs for this witness are
  (1,2) and (3,2) (both sides equal 1); the (1,3) pair has slack 1/2.
- **Note.** "gap >= 1/4" for (1,3,5,7) is true but the actual gap is 1/2
  (see 4.5).

None of these affect the document's theorems, its adjudication, or its
conclusions.

## 7. What this does and does not establish

Established: within n <= 5 and v_n <= 50, the polytope P(v) is
integer-feasible for every speed vector, with machine-verifiable certificates;
the LP relaxation is provably always feasible (so the integrality question is
the whole question); the document's reduction, corrected formulation,
bounded-speed theorem, union and overlap bounds, and tightness claims all
verify exactly; three annotation-level errata were found and corrected.

Not established: integrality of P(v) in general, and therefore the Lonely
Runner Conjecture. The enumeration is finite; it covers a range where the
conjecture was already proven by other means (n <= 7). The value of the check
is that it validates the *reduction itself* — the k_i-formulation, the polytope,
and the integrality framing — on millions of instances, and it supplies the
tight-set and second-tightest censuses that any future proof must saturate.

The natural next steps, in the document's own framing: push the enumeration to
n = 6, 7 (C(40,6) = 3,838,380 vectors; the committed program runs this
unchanged), tabulate the 2/(2n+1) minimizers against the overlap bound, and
attempt a total-dual-integrality or circulation-style argument on the
constraint matrix, for which the committed tight-set census now provides exact
test data.
